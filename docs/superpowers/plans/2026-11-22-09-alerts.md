# Implementation Plan: Prompt 09 — Alerts

**Goal:** Implement data-driven alert rules engine with seed configuration, scheduled evaluator managing firing/resolved states, cooldowns, silences, sustained-threshold logic, dry-run testing, and dual-tab frontend UI with a global header alert bell.

---

## Phase 1: Configuration, Models & Alembic Migration
- [x] Task 1.1: Populate `config/alerts.yaml` with seed alert rules.
- [x] Task 1.2: Add alert settings to `config/app.yaml` and `backend/app/core/config.py` (`alert_eval_interval_seconds: 15`, `alert_default_cooldown_minutes: 15`).
- [x] Task 1.3: Create models in `backend/app/models/alert.py`: `AlertRule`, `AlertEvent`, `AlertSilence` and register in `backend/app/models/__init__.py`.
- [x] Task 1.4: Create Alembic migration `0005_alerts.py` for tables `alert_rules`, `alert_events`, `alert_silences`.

## Phase 2: Schemas & Seed Loader
- [x] Task 2.1: Define Pydantic schemas in `backend/app/schemas/alert.py`:
  - `AlertRuleCreate`, `AlertRuleUpdate`, `AlertRuleResponse`, `AlertRulesListResponse`.
  - `AlertEventResponse`, `AlertEventsListResponse`, `AlertEventAckRequest`.
  - `AlertSilenceCreate`, `AlertSilenceResponse`.
  - `AlertDryRunRequest`, `AlertDryRunResponse`, `AlertTargetMatch`.
- [x] Task 2.2: Implement `seed_alert_rules` utility to bootstrap rules from `config/alerts.yaml` on first startup.

## Phase 3: Alert Service & Evaluator Engine
- [x] Task 3.1: Implement `AlertEvaluatorService` in `backend/app/services/alert_evaluator_service.py`:
  - Background evaluation loop (`start()`, `stop()`).
  - Scope matching (`all`, `label`, `container`).
  - Active silence and cooldown check.
  - Evaluation of rule types: `container_down`, `restart_loop`, `health_failing`, `cpu_high`, `memory_high`, `disk_high`, `host_load`, `container_missing`.
  - Sustained-threshold logic over `duration_minutes` using `container_metrics` table.
  - State machine: transitions to `firing` and `resolved`.
- [x] Task 3.2: Implement `AlertService` in `backend/app/services/alert_service.py`:
  - Rules CRUD.
  - Dry run evaluation (`dry_run_rule`).
  - History query with filters (`status`, `severity`, `rule_id`).
  - Acknowledgment (`acknowledge_event`) with audit logging.
  - Silence creation (`create_silence`) with audit logging.
  - Active alert count query.
- [x] Task 3.3: Wire `AlertEvaluatorService` in `backend/app/main.py` lifespan.
